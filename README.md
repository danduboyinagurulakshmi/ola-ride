# Ola Ride Insights

An end-to-end ride analytics project using the supplied July 2024 Ola bookings workbook. It includes a reproducible cleaning/EDA pipeline, ten SQL analyses, an interactive Streamlit dashboard, and Power BI measures and setup guidance.

## Dataset

Place `OLA_DataSet.xlsx` in `data/` (the uploaded workbook and its cleaned CSV are included there). The loader reads the `July` worksheet; the other worksheets contain supplementary/pivot-style material. The observed July sheet has 103,024 rows and 20 columns, covering July 1–31, 2024. Booking IDs are unique in the source. Literal `"null"` strings are normalized to missing values, numeric fields are coerced, invalid ratings and negative measures are excluded as missing, and duplicate booking IDs are removed.

The pipeline adds a combined booking timestamp, booking hour, weekday, and weekend flag. The decorative vehicle-image URL is omitted from the cleaned table. Missing values are retained as missing rather than filled with artificial values.

## Run locally

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
streamlit run app.py
```

By default, the app reads the pre-cleaned `data/cleaned_bookings.csv` for faster startup. If that file is absent, it falls back to `data/OLA_DataSet.xlsx`. Set `OLA_DATA_PATH` to use another CSV or workbook:

```powershell
$env:OLA_DATA_PATH = "C:\path\to\OLA_DataSet.xlsx"
streamlit run app.py
```

The dashboard offers date, status, vehicle, and payment filters; overall, vehicle, revenue, cancellation, and rating views; a SQL explorer; and CSV downloads. SQL question outputs use the active filters.

## Cleaning and EDA exports

```powershell
python -m scripts.run_eda
```

This refreshes `data/cleaned_bookings.csv` and writes `reports/cleaned_bookings.csv`, `reports/data_quality.csv`, and `reports/eda_summary.csv`. Report exports are git-ignored; regenerate them when needed.

## SQL questions

`sql/queries.sql` contains runnable SQLite statements for all ten requested questions. The Streamlit SQL explorer runs these statements over an in-memory SQLite copy of the cleaned, filtered data. In particular:

- Ride-distance averages exclude unsuccessful bookings and zero-distance records.
- Revenue sums `booking_value` only for `Success` bookings.
- Customer and driver cancellations are identified by their booking status; driver reasons are grouped from `canceled_rides_by_driver`.
- The incomplete-ride query includes explicit incomplete flags and an `Incomplete` booking status.

## Power BI

Power BI Desktop can import `reports/cleaned_bookings.csv` generated by the EDA command, or connect to a cleaned CSV exported from the app. Follow [Power BI setup](powerbi/README.md) for the suggested model, visuals, slicers, and DAX measures. A `.pbix` file is not generated by this Python project; save the report from Power BI Desktop after connecting the data.

## Validation

Run the focused unit tests with the Python standard library:

```powershell
python -m unittest discover -s tests -v
```

The tests cover cleaning/null handling, duplicate removal, derived date features, and execution of every SQL statement against a representative table.
